Rules that apply to every page
  Navigation (researcher): Overview · My Profile · Scientific Outputs · Resources & Guidance · Help &
  Contacts. No "Support Requests", no "Welcome Pack" as a menu item.

  Status line on every page: one compact line at the top, always visible, e.g. "UNIDCOM: Under review ·
  Website: Not published". The full timeline lives only on the Overview.

  Nothing is published automatically. Publishing to the website is always a separate UNIDCOM decision.
  Never show "Auto-published".

  ORCID in v1.0 is import only (ORCID → RIMS). Label actions "Import from ORCID", not "Sync". Two-way sync
  is v2.0; do not show a button for it now.

  Info icon (i) on every field and action, with one short sentence explaining it on hover.

  Visual style: the dark sidebar from version A (as the platform already has) with the lighter content area of
  version B. Calm yellow for alerts, not red.

Platform checks before the demo
These are about the business layer and behaviour, not the data. Data content (missing DOIs, records not
on ORCID, outdated entries imported from Notion) is expected: each researcher reviews and corrects
their own record during the pilot, and submits the version they consider final for the website.
                                                                    RULE

  Imported records start as "To be validated by the researcher". Records imported from Notion/Sanity must
                                                                 not appear as "Approved" (the admin
                                                                 currently shows "Outputs approved
                                                                 365/365"). Approval only happens after the
                                                                 researcher submits and UNIDCOM reviews.
                                                                 This is what makes the pilot meaningful.

                                      FLOW

  Website publishing end to end. Show one profile going Submitted → Approved → Publish to website → visible
                                 on the site (Sanity).

                              TECH

  Permission error on load. The browser console shows "permission denied for table people" (401). Check
                            Supabase row-level security for the researcher role.

                                     UI

  Landing page and duplicates. After login the app opens "Resources & Guidance"; it should open the Overview.
                               "Connect ORCID" appears twice on My Profile.

Brief for AI coding agents
Plain-text version of this page, written to be pasted into an AI coding assistant. It is self-contained: every
component is described in words, so the agent does not need the images. IDs are only labels for tracking.
  Copy brief

  SO-5 MUST: A line of counters under the filters ("12 outputs · 3 journals · 9 conferences · 2
  with issues") that updates with the selected filters.
  SO-6 MUST: Each output is one clickable row (no "View" button): type · subtype tag on the left;
  title; venue · year underneath; on the right, the issue written in full ("Missing DOI",
  "Affiliation mismatch", "Not on ORCID") or "No issues"; and the star.
  SO-7 MUST: A banner at the top "N new publications in ORCID -> Review" that opens the existing
  ORCID reconciliation view (keep that view as it is).
  SO-8 MUST: Button "+ Add output" at the top right opens a step-by-step wizard: type -> subtype ->
  details -> project -> review.
  SO-9 MUST NOT: dropdown filters, a table layout, or ORCID shown only as ✓/✗ icons.
